# htd — 도형 랜덤 디펜스 설계

- 날짜: 2026-10-02
- 대상 기기: iPhone 13 Pro (Safari, 홈 화면 PWA)
- 벤치마크: 쉐이퍼즈: 랜덤 디펜스(유닛·필드·소환·합성), 공략불가 운빨 디펜스(적 순환·도박·신화 조합법)

## 1. 목표와 범위

싱글 오프라인 무한 웨이브 랜덤 디펜스. 서버 없음. 아이폰에서 홈 화면에 추가해 전체화면·오프라인으로 실행한다.

v1 제외: 사운드, 타일 강화, 멀티플레이·랭킹, 메타 성장(판을 넘는 영구 업그레이드).

## 2. 게임 규칙

모든 수치는 `src/sim/balance.ts` 한 곳에 상수로 둔다. 아래 숫자는 초기값이다.

### 2.1 필드

- 세로 화면 중앙에 6×6 = 36칸. 한 칸에 쉐이퍼 1개.
- 적은 필드 바깥 사각 테두리 경로를 시계 방향으로 끝없이 순환한다.

### 2.2 쉐이퍼

쉐이퍼 = 속성 × 단계.

| 속성 | 고유 효과 |
|---|---|
| 🔥 불 | 화상(지속 피해) |
| 💧 물 | 감속 |
| 🌪 바람 | 빠른 연사, 연쇄 공격 |
| 🪨 땅 | 고데미지, 기절 확률 |
| ✨ 빛 | 주변 8칸 아군 공격력 버프 |
| 🌑 암 | 적 방어력 감소 |

단계(꼭짓점 수로 표현): ▲1 → ■2 → ⬟3 → ⬢4 → ●5(최대). 단계가 오르면 공격력·사거리·이펙트가 커진다.

신화 ✸: 조합법으로만 얻는 별도 유닛(2.6).

### 2.3 소환

- 비용 고정: SP 10.
- 결과: 무작위 속성(6종 균등), 단계 ▲ 95% / ■ 5%.
- 배치: 빈 칸이 있으면 무작위 빈 칸, 필드가 가득 차면 유닛 서랍으로.
- 필드와 서랍이 모두 가득 차면 소환 버튼 비활성.
- SP 획득: 적 처치, 웨이브 클리어. 시작 SP 100.

### 2.4 조작

| 동작 | 결과 |
|---|---|
| 드래그 → 같은 속성·같은 단계 쉐이퍼 | 합성: 속성 유지, 단계 +1 (예: 🔥▲ + 🔥▲ → 🔥■). ●끼리는 합성 불가 |
| 드래그 → 빈 칸 | 이동 |
| 드래그 → 다른 쉐이퍼 | 자리 교환 |
| 드래그 → 서랍 | 보관 |
| 탭 | 선택: 하이라이트 + 정보 팝업(속성·단계·공격력)과 "판매 (+N SP)" 버튼. 판매 버튼을 누르면 판매(SP 일부 환급, 단계별 차등). 다른 곳을 탭하거나 드래그를 시작하면 선택 해제 |

합성 결과는 드롭한 대상 칸에 생기고, 드래그한 원래 칸은 빈다.

### 2.5 유닛 서랍

- 위치: 필드 아래, 버튼 바 위의 가로 스크롤 HTML 패널.
- 같은 쉐이퍼끼리 묶어 개수 배지로 표시(`🔥▲×3`).
- 용량: 총 20개.
- 공격하지 않는다(보관 전용).
- 서랍 → 필드: 같은 쉐이퍼 위로 드롭하면 합성, 빈 칸이면 배치, 다른 쉐이퍼 위면 교환(밀려난 쉐이퍼는 서랍으로).
- 묶음 탭 = 선택: "판매 (+N SP)" 버튼(1개 판매)과, 개수 2 이상이면 "합성" 버튼(2개 → 다음 단계 1개, 서랍에 남음)이 뜬다.

### 2.6 신화 조합법

- 정해진 재료 조합(속성+단계)을 필드와 서랍을 합쳐 모으면, 재료를 소모하고 신화 ✸ 1개를 만든다. 예: 🔥⬢ + 💧⬢ + 🌪⬟ → 「폭풍증기」.
- 신화 4~6종. 각자 고유 공격 패턴을 가진다.
- 재료 소모 우선순위: 필드 먼저, 부족분만 서랍에서.
- 결과물 배치: 필드 재료를 1개 이상 소모했다면 조합법 순서상 첫 번째로 소모된 필드 칸에 생긴다(필드 재료 소모로 빈 칸이 반드시 생기므로 항상 가능). 재료가 전부 서랍에서 나왔다면 필드 빈 칸 중 무작위, 빈 칸이 없으면 서랍(재료가 빠져 자리가 있음).
- 조합 가능하면 추천 조합 버튼이 빛난다. 도감 모달에서 조합법과 발견 여부를 본다.

### 2.7 도박

행운석으로 뽑는다. 행운석은 보스 처치 시 2개, 5웨이브마다 1개 얻는다.

| 사용 | 성공 확률 | 결과 |
|---|---|---|
| 1개 | 60% | ■ |
| 2개 | 25% | ⬟ |
| 3개 | 10% | ⬢ |

속성은 무작위. 실패하면 아무것도 얻지 않는다. 배치 규칙은 소환과 같다.

### 2.8 강화

SP로 속성별 공격력을 올린다(6트랙, 판 안에서만 유지). 비용은 레벨마다 증가.

### 2.9 상성

- 웨이브마다 적에게 속성 하나가 붙는다. 다음 웨이브 속성을 HUD에 미리 표시.
- 순환: 🔥 > 🌪 > 🪨 > 💧 > 🔥. 빛 ↔ 암은 서로 우위.
- 우위 ×1.5, 열세 ×0.7, 그 외 ×1.0.

### 2.10 웨이브와 패배

- 약 20초마다 웨이브 시작, 웨이브마다 적 무리 스폰. 웨이브가 오를수록 HP 증가.
- 10웨이브마다 보스. 60초 안에 처치하지 못하면 패배.
- 필드 위 적이 100마리 이상이면 패배.
- 무한 모드. 도달 웨이브가 점수.

### 2.11 편의

1×/2× 배속, 일시정지.

## 3. 아키텍처

스택: TypeScript + PixiJS v8 + Vite. UI는 HTML/CSS 오버레이.

```
src/
├─ sim/          순수 TS, 브라우저 API 금지
│   ├ board.ts     필드 + 서랍: 합성/이동/교환/판매/보관
│   ├ combat.ts    순환 경로 이동, 타겟팅, 투사체, 상성·디버프
│   ├ waves.ts     웨이브/보스 스케줄, 패배 판정
│   ├ economy.ts   SP, 소환, 도박, 강화, 신화 조합법
│   ├ rng.ts       시드 기반 RNG
│   ├ balance.ts   모든 수치 상수
│   └ game.ts      Game: step(), command(), 이벤트 큐, 직렬화
├─ render/       PixiJS. sim 상태를 읽기만 한다
├─ ui/           HUD, 버튼바, 서랍, 모달(도박·강화·도감·게임오버)
├─ input.ts      탭/드래그 제스처 → command
└─ main.ts       고정 스텝 루프 + 보간 렌더
public/          manifest, sw.js, 아이콘
tests/           sim 단위 테스트, 헤드리스 자동 플레이
```

### 3.1 원칙

- sim은 결정론적이다: 같은 시드 + 같은 명령 시퀀스 → 같은 결과. 고정 스텝 60Hz.
- 렌더는 sim과 분리하고 보간한다. 화면 주사율(60/120Hz)과 무관하게 게임 속도가 같다.
- 모든 상태 변경은 `command()`로만 한다. 명령: `Summon`, `Move{from,to}`, `Sell{slot}`, `Gamble{stones}`, `Upgrade{element}`, `Craft{recipe}`, `SetSpeed`, `Pause`. 슬롯은 필드 칸 또는 서랍 묶음을 가리킨다. 잘못된 명령은 상태를 바꾸지 않고 거절 이벤트를 낸다.
- 이벤트 큐: 합성, 소환, 보스 등장, 웨이브 시작, 패배 등. UI가 매 프레임 비운다.
- UI 갱신: sim이 `uiVersion`을 올렸을 때만 HUD/서랍을 다시 그린다.

### 3.2 성능

- 적·투사체·파티클은 객체 풀로 재사용(프레임당 할당 없음).
- 도형 텍스처는 시작 시 1회 생성하고 이후 Sprite 배치 렌더링.
- 캔버스 DPR 상한 2.
- 디버그 FPS 오버레이(토글).

### 3.3 입력

- 필드는 캔버스, 서랍은 HTML이다. 드래그는 `input.ts`가 통합 처리하고, 드래그 중에는 HTML 고스트 요소를 띄운다.
- 드롭 좌표 → 필드 칸 판정은 필드 레이아웃 함수로 한다.
- 탭과 드래그 구분: 이동 거리 8px 미만으로 손을 떼면 탭.
- 판매는 2단계: 탭으로 선택 → 판매 버튼. 실수 판매를 막는다.

### 3.4 저장

- `localStorage` 키 접두사 `htd:`.
- 영구: 최고 웨이브, 발견한 신화, 설정(배속·FPS 오버레이).
- 진행 중인 판: `visibilitychange`(hidden)와 일시정지 때 sim 상태를 직렬화해 저장하고, 다시 열면 이어 한다. 패배하면 삭제.
- 로드 시 버전·구조·크기(최대 256KB)를 검증하고, 실패하면 버리고 새 판.
- 모든 storage 접근은 try/catch.

## 4. PWA와 배포

- 배포 주소: `https://jeonhojin.github.io/htd/` (GitHub Pages, 저장소 `JeonHoJin/htd`).
- 설치: Safari에서 열고 공유 → 홈 화면에 추가.
- manifest: `display: standalone`, `orientation: portrait`, 아이콘, `apple-touch-icon`.
- 뷰포트: `viewport-fit=cover`, safe-area inset 처리, 확대·더블탭 줌·롱프레스 콜아웃·텍스트 선택·스크롤 바운스 차단.
- service worker: 빌드 산출물을 캐시 우선으로 제공해 오프라인 실행. 캐시 이름 `htd-<버전>`, `htd-` 접두사 캐시만 정리. 새 버전 감지 시 "업데이트" 버튼.
- 개발: `vite --host`로 같은 네트워크의 아이폰에서 확인.
- CI: GitHub Actions에서 타입체크 → 테스트 → 빌드 → Pages 배포. 액션은 커밋 SHA로 고정, `persist-credentials: false`, 권한 `contents: read`, `pages: write`, `id-token: write`.

## 5. 보안

백엔드가 없으므로 공격면은 페이지와 로컬 저장소다.

- CSP 메타 태그: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; connect-src 'self'; worker-src 'self'; manifest-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'`. `referrer`는 `no-referrer`.
- PixiJS는 `pixi.js/unsafe-eval` 모듈(eval 대체 폴리필)을 써서 `'unsafe-eval'` 없이 동작시킨다. 텍스처 로더 워커는 끈다. 구현 후 콘솔에 CSP 위반이 없는지 확인한다.
- 인라인 스크립트·서드파티 CDN 금지. 의존성은 npm으로 번들.
- 프레임 버스터(외부 스크립트).
- 에러 바운더리: `error`/`unhandledrejection` → 오버레이에 "새로고침", "로컬 데이터 초기화".
- 저장 데이터는 신뢰하지 않는다(3.4 검증). 화면에 넣는 문자열은 `textContent`로만.
- 공개 저장소: 비밀·실사용자 데이터 커밋 금지. 커밋 전 diff와 메시지 유출 스캔.

## 6. 테스트

- Vitest 단위 테스트(sim):
  - 합성: 같은 속성·단계만, 속성 유지, ● 상한
  - 이동/교환/보관, 서랍 용량·묶음·서랍 내 합성·서랍→필드 교환
  - 고정 비용 소환, 필드 가득 → 서랍, 둘 다 가득 → 거절
  - 신화 조합: 필드+서랍 재료 집계, 필드 우선 소모, 결과가 첫 소모 필드 칸에 배치, 전부 서랍 재료일 때 배치
  - 도박 확률(고정 시드로 분포 확인), 행운석 지급
  - 상성 배율, 디버프
  - 웨이브 스케줄, 보스 제한시간 패배, 적 100마리 패배
  - 직렬화 왕복, 깨진 저장 데이터 거절
  - 결정론: 같은 시드+명령 → 같은 상태
- 헤드리스 자동 플레이 봇: 단순 전략(소환·합성·조합 우선)으로 수백 판을 돌려 도달 웨이브 분포를 출력하는 밸런스 리포트(`npm run balance`).
- 실기기: iPhone 13 Pro에서 FPS 오버레이로 확인. 확인 항목: 설치, 오프라인 실행, 백그라운드 후 이어하기, 탭 선택·판매 버튼·드래그, 안전영역.
